## Layout
- `main/`, `clean/`, `dirty/` + `<FAMILY|GEN>/<name>.csv`: the three variants of each of the 35 files, same header and row count.
  - F-main: the primary data, moderately messy (letter-case and space noise in text columns, about 1-9% empty cells in
    some columns, more in two optional columns: trip ratings about 19%, footfall remarks about 47%; a "-" placeholder in
    one column). Some files are clean on purpose where a mechanism needs exact data.
  - F-clean: the true values; no empty cell, no "-" placeholder, no letter-case or space noise.
  - F-dirty: F-main plus about 5% of the non-empty numeric cells written as `$<value>` or `N/A` (every numeric column has at
    least one `$` cell, so it reads as text), and about 2% (at least one) whitespace-only labels in every category-like
    column. Identifier, date, boolean and free-text columns are as in F-main.
- `descriptions.tsv`: one line per file describing F-main (`path, rows, columns, description`); numbers are measured from
  the F-main rows at generation time; lint-clean (`harness/lint_prompts.py`). Task files copy these lines verbatim.
- `columns.tsv`: `path, column, kind, paraphrase_type`. `kind` is the generator's column kind; `paraphrase_type` maps it to
  the section 4.3 R paraphrase type table (general text, date-like text, integer numeric, float numeric, zero-padded id,
  category-like key; `-` = not a target: integer row ids and booleans). "First matching column in file order" = first row
  of this file for the path with the wanted type.
- `row_files.tsv`: each CONFIRMED catalogue row -> the F-main file(s) and columns its confirmation program uses on F-main
  (`mechanisms/confirm/fmain/<id>.py`). For stratum M task authors.
- `PACKAGE_STATUS.md`: FIX package status.
